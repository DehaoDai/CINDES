# Software and hardware

The experiment uses NumPy, PyTorch, and the Python standard library. Table construction, result validation, study planning, and archive creation use only the standard library. LaTeX is needed only to compile the table source. The Unix locking used by the launcher requires Linux, macOS, or Linux under WSL.

## Recorded SCC environment

The successful runs for n=500,1000,1500 recorded the following environment:

| Component | Recorded value |
| --- | --- |
| Python | 3.13.5 |

The 60 successful pairs used 24 NVIDIA L40S, 20 NVIDIA A100 80GB PCIe, 15 NVIDIA A40, and one NVIDIA H200 NVL allocations. Both methods within a pair used the same allocation. The per-pair software and hardware fields retained from the successful runs appear in `reported_results/environment_summary.csv`.

The earlier n=2000 archive contains numerical results and scientific settings but lacks per-run environment metadata. Those fields are left empty and marked unavailable in the environment summary. Earlier console output reported the same NumPy and PyTorch versions, but it is not a complete environment record for every historical replication.

## SCC activation and GPU ownership

The default `scc_env.sh` unloads a conflicting `python3` module, loads Miniconda and the academic-ml module, and activates the recorded environment. Activation occurs before enabling Bash nounset handling. A custom activation script can be supplied through `--env-script`; it must make the selected Python executable and its dependencies available.

The launcher respects the scheduler's GPU assignment and CPU allocation. It does not change CUDA visibility in SCC jobs. The environment check runs in a short-lived child process, which exits before the training child starts. This preserves the corrected GPU ownership behavior used in the successful study.

The ordinary SCC allocation is four CPU slots and one GPU. The scientific helper reads the allocated thread count, and `run_original.py` enforces the requested cap before calling the driver. New run metadata records the actual thread count, software versions, CUDA runtime, and GPU.

## Package preparation check

A real reduced CPU check completed with Python 3.12.14, NumPy 2.3.5, and PyTorch 2.15.0+cpu using one thread. Both methods trained, generated observations, evaluated metrics, and produced valid summaries and a results archive. This was an installation check at n=64 and d=7, not a reproduction of the full-setting GPU results. Its receipt is `verification/cpu_smoke_check.json`.

`requirements.txt` specifies API minimums rather than exact historical versions. A compatible CPU PyTorch build is sufficient for the smoke check; the full GPU study requires a compatible CUDA build. Fixed seeds do not guarantee identical floating-point outputs across software or hardware changes. Runtime is also environment-dependent, so preserve the metadata generated by each fresh run.
