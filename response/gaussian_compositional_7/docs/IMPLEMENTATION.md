# Experimental design and implementation

This document describes the unbounded, seven-dimensional compositional experiment. The full profile contains 20 paired replications at each sample size $n\in\{500,1000,1500,2000\}$. The code for the earlier bounded tree and probit experiments is not part of this study.

The 14 Python files under `experiment/` are unchanged from the files recorded by the completed study. Their SHA-256 hashes appear in `experiment/original_python_sha256.json`. The shell scripts provide execution instructions for the journal package; they do not change the statistical experiment. The main entry points are `prepare_reference.py`, `run_task.py`, and `summarize_results.py`. Some helper modules contain earlier training routines that are retained to preserve the original source files. The full study calls the training routines in `source/balanced_training.py` through `run_task.py`.

## 1. Data-generating distribution

Let $\phi_7$ denote the standard Gaussian density on $\mathbb R^7$. Write $u_j=\tanh(x_j)$ and define

$$
v=\mathbb E[\tanh^2(Z)],\qquad Z\sim N(0,1),
$$

$$
H(x)=\frac{-u_4u_2-u_4u_5-u_2u_6-u_2u_3+u_5u_1+u_5u_7}{v\sqrt{6}},
\qquad
p(x)=\frac{\phi_7(x)\exp\{1.5\tanh(H(x))\}}{Z_g}.
$$

The constant $v$, approximately $0.39429449039784126$, is computed by one-dimensional quadrature. The generating coefficients are fixed by potential seed 11. The coordinate indices in the displayed formula are one based; the Python arrays use zero-based indices.

The six pairs entering $H$ are $(4,2),(4,5),(2,6),(2,3),(5,1),(5,7)$. The outer function $\tanh$ introduces interactions beyond individual pair terms, so these pairs are not asserted to form a conditional-independence graph for $p$. Since the tilt is bounded, $p$ has full support on $\mathbb R^7$ and sub-Gaussian tails.

Observations are generated by rejection sampling. A proposal $X\sim N(0,I_7)$ is accepted with probability $\exp\{1.5\tanh(H(X))-1.5\}$. This produces independent target observations, exactly in real arithmetic. Coordinates are never clipped. The DGP is implemented in `experiment/source/compositional_dgp.py`.

## 2. Replications and random seeds

Each replication draws a new dataset and fits both methods to that dataset. The methods also use the same cross-validation partition. The 20 replications at a fixed sample size are the units used to calculate the reported mean and standard deviation.

| Task IDs | Sample size | Replication IDs | Training seeds |
| --- | ---: | --- | --- |
| 1--20 | 500 | 1--20 | 1000--1019 |
| 21--40 | 1000 | 1--20 | 1020--1039 |
| 41--60 | 1500 | 1--20 | 1040--1059 |
| 61--80 | 2000 | 1--20 | 1060--1079 |

There are 80 paired runs, 160 final fitted models, and 2,400 cross-validation fits. The full seed rules are recorded in `study.make_config()` and in each output directory's `study_manifest.json`. The evaluation reference uses separate random seeds. The true density, $H$, its pairs and signs, and the target-reference observations are used to generate data or evaluate results; they are not supplied to either estimator during training or cross-validation.

## 3. Networks, objectives, and model selection

Both methods use fully connected networks with two hidden layers of 64 Softplus units. The Softplus parameter is 5 and its numerical threshold is 20. CINDES has a scalar output. DSM has seven outputs and receives the observed coordinates together with 16 sinusoidal time features. The hidden-layer sizes match, while the total parameter counts are 4,737 for CINDES and 6,151 for DSM.

CINDES is trained to distinguish observed data from a fixed $N(0,I_7)$ reference. Each batch contains at most 256 observed points and two newly drawn Gaussian reference points per observed point. Binary cross-entropy is averaged over the combined batch. Classifier logits are clipped to $[-25,25]$; this does not truncate the observations or the support of the estimated density. With the 1:2 class proportions, the population logit differs from $\log(p/\phi_7)$ by a constant. That constant cancels from density normalization and the normalized Monte Carlo score weights.

DSM uses the score parameterization $s_\theta(y,t)=-y+g_\theta(y,t)$. For each observed point $X$, it draws $t$ uniformly on the logarithmic scale over $[0.001,3]$ and independent $\epsilon\sim N(0,I_7)$, then forms

$$
Y_t=e^{-t}X+\sqrt{1-e^{-2t}}\,\epsilon.
$$

The denoising loss is the mean of $(\sqrt{1-e^{-2t}}\,s_\theta(Y_t,t)+\epsilon)^2$ over observations and coordinates. Both methods add $\lambda$ times the mean absolute value of all linear-layer weights, including output weights and excluding biases. Adam is applied to this penalized objective. This encourages small weights; it does not perform proximal thresholding or explicit graph selection.

For each method, three-fold cross-validation jointly selects the penalty from $\{0,0.01,0.1,0.3,1\}$ and the number of training epochs. Training is capped at 2,000 complete epochs over the observed data available in that fit. The last partial batch is retained. Validation is evaluated at initialization and after every 20 epochs. Fold losses are weighted by validation-fold size. Exact ties favor the smaller penalty and then the earlier stopping point.

CINDES is selected by held-out normalized density negative log-likelihood, with 65,536 fixed Gaussian draws used to estimate its normalizing constant in each fold. The common Gaussian log-density term can be omitted from this selection criterion. DSM is selected by held-out denoising loss using eight fixed time/noise draws per validation point. These numerical loss values are used within a method; they are not compared across methods.

The chosen model is refitted on all $n$ observations for the selected number of epochs. Both methods use Adam with initial learning rate $0.001$, zero weight decay, and a cosine learning-rate schedule indexed by optimizer updates. The schedule retains the original full training horizon after the stopping point has been selected. Cross-validation and final refitting run on CPUs, with one numerical thread per fit and up to four concurrent fit workers in the full study.

## 4. Score approximation and sample generation

For CINDES, let $\widehat f_R$ be the fitted clipped logit, $m_t=e^{-t}$, and $\sigma_t=\sqrt{1-e^{-2t}}$. At a score query $(y,t)$, the code draws 2,500 independent Gaussian vectors $\epsilon_k$ and forms 5,000 antithetic particles

$$
z_k^+=m_ty+\sigma_t\epsilon_k,\qquad z_k^-=m_ty-\sigma_t\epsilon_k.
$$

Let $w_k^+$ and $w_k^-$ be the weights proportional to $\exp\{\widehat f_R(z_k^+)\}$ and $\exp\{\widehat f_R(z_k^-)\}$, normalized jointly over all 5,000 particles. The estimated score is

$$
\widehat s(y,t)=-y+\frac{m_t}{\sigma_t}\sum_{k=1}^{2500}(w_k^+-w_k^-)\epsilon_k.
$$

The antithetic construction gives the exact Gaussian score $-y$ when the classifier is constant. The finite-particle, self-normalized estimator can still be biased for a nonconstant classifier. Its implementation is `cindes_score()` in `experiment/source/subgaussian_methods.py`.

Both methods start generation from $N(0,I_7)$ and use $T=3$, $\delta=0.001$, and $M=200$ reverse steps. In reverse elapsed time, the first 100 steps are equally spaced from 0 to $T-1$; the remaining steps give geometrically decreasing forward times from 1 to $\delta$. For a step of size $h$, both methods use the update

$$
y_{\mathrm{next}}=e^{-h}y+2(1-e^{-h})(\widehat s(y,t)+y)+\sqrt{1-e^{-2h}}\,\xi,
\qquad \xi\sim N(0,I_7).
$$

Noise is retained in every step, including the last. There is no additional CINDES terminal-sampling step, final denoising step, or support clipping. Each fitted model generates 10,000 observations in ten resumable blocks of 1,000, using GPU batches of 128. Initial Gaussian draws and reverse-noise streams are paired between methods; CINDES's particle stream is separate. Calculations use float32, deterministic Torch algorithms, and disabled TF32. Each paired task checks the production sampler against the original sampler before generating its study samples.

## 5. Evaluation and table entries

A shared evaluation sample contains 1,048,576 independent target observations, arranged in eight banks of 131,072. An additional 20 independent target samples of size 10,000 provide finite-sample calibration values. Neither the reference nor the calibration samples enter fitting. Calibration values are recorded separately and are not subtracted from the reported discrepancies.

All histograms use 20 fixed bins with boundaries $b_j=\Phi^{-1}(j/20)$, including $b_0=-\infty$ and $b_{20}=\infty$. TV1 averages histogram total variation over the seven coordinates. TV2 averages histogram total variation over the six pairs entering $H$, rather than all 21 coordinate pairs. Each histogram TV is one half the sum of absolute bin-probability differences between generated and target-reference samples.

For $H$-TV, the same bins are applied to the scalar $H$-values. For $H$-$W_1$, the code uses the unbinned empirical distributions and calculates

$$
W_1(\widehat P_H^{\mathrm{gen}},\widehat P_H^{\mathrm{ref}})=\int_{\mathbb R}\left|\widehat F_H^{\mathrm{gen}}(t)-\widehat F_H^{\mathrm{ref}}(t)\right|\,dt.
$$

The use of Gaussian quantile boundaries is a fixed binning convention; it does not assume that $H(X)$ is Gaussian. The Wasserstein statistic is a one-dimensional distance on $H$-values, not a Wasserstein distance between the full seven-dimensional distributions.

LLgap is the reference mean minus the generated mean of $\ell(x)=\log\phi_7(x)+1.5\tanh(H(x))$. The unknown normalizing constant cancels. This signed moment difference is not a KL divergence and need not be nonnegative. All individual LLgaps were positive in the reported experiment.

For each sample size and method, table entries are the mean and sample standard deviation over the 20 replications, with standard deviation denominator 19. The code also records standard errors, paired differences, selected penalties and durations, and additional diagnostics. Boldface in the accuracy table indicates a lower CINDES mean for the nonnegative discrepancy measures, or a mean closer to zero for LLgap, at the same sample size. All reported LLgap means are positive, so these rules give the same highlighted entries for the submitted results. Boldface does not indicate a significance test.

## 6. Computation times

Final refit is the recorded elapsed time spent refitting the selected model on all $n$ observations. It excludes cross-validation and setup before the training timer. Generation time adds the elapsed durations of the ten completed sample blocks, including their timed recording and file-writing work. The CUDA device is synchronized before the generation timer ends. Model loading and the sampler preflight are excluded.

Refit plus generation is computed within each replication before its mean and standard deviation are calculated. The cross-validation column adds the elapsed durations of the 15 individual fits for each method, including validation. The fits were run in parallel, so this sum is cumulative fitting time, not the elapsed duration of the combined parallel stage. It is also not a measurement of CPU process time. Queue waiting is excluded from the reported timings.

Both methods used the same allocated GPU within each replication. Across the 80 completed paired runs, the allocations were 64 NVIDIA L40S, 14 NVIDIA A40, and 2 NVIDIA RTX PRO 6000 Blackwell Server Edition GPUs. The recorded environment was Python 3.13.5, NumPy 2.5.2, SciPy 1.18.1, and PyTorch 2.13.0+cu132, with CUDA runtime 13.2. Repeating the experiment on another environment can change numerical results and elapsed times. The included reported-result records permit exact reconstruction of the submitted tables without rerunning the training or generation stages.

## 7. Execution details and checks

The execution code uses Python, NumPy, SciPy, and PyTorch. Filesystem locking uses the standard-library `fcntl` module, so the experiment runs on Unix-like systems. Windows users can use a Linux environment such as WSL. The full profile requires a CUDA GPU and fails if CUDA is unavailable. The smoke profile is a small CPU implementation check: one $n=500$ pair, two penalties, two training epochs, 20 score particles, four reverse steps, 64 generated observations, and smaller reference banks. Its output is not a replication of the reported scientific results.

New output directories contain a frozen study manifest and source snapshot. Completed stages are checked by hashes and reused on a compatible environment. If unfinished generation resumes on a different GPU model or numerical runtime, the existing generation artifacts are archived and both methods are regenerated using the frozen fitted models. Do not change the Python sources within an ongoing study.

The original implementation checks can be run from `experiment/` with

```bash
python qa_checks.py --static --sampler --runtime
```

The historical `--submission` check in the preserved Python source expects the original laboratory-specific SCC project and exact original scheduler arguments. It is not the test for the journal package's configurable submission wrapper. The new wrapper is checked separately without submitting actual cluster jobs. See the top-level README and the package verification records for the commands and checks performed for this distribution.

The SCC shell wrapper now requires the caller's `SCC_PROJECT`, propagates an explicit output directory, and can source a caller-supplied environment activation script. Its resource requests remain four CPU slots and one GPU per paired task, with at most two array tasks active at once. The 12-hour request is a per-task limit; total completion time depends on queue availability. The default module commands reproduce the recorded BU SCC environment when those modules are available.

NumPy, SciPy, and PyTorch are imported dependencies and are installed separately from this package.
